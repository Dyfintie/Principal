## Provider documentation checked

- [Antigravity headless mode](https://antigravity.google/docs/cli/headless): supported EOF shutdown, stream message formats, headless soft denial, partial responses and output schema behavior.
- [Antigravity permissions](https://antigravity.google/docs/permissions): scoped allow/deny rules and permission bypass behavior.

## Verification

Regression tests cover JSON redaction and legacy corrupt events; structured failure classification; symlink checkpoint and imported-patch rejection; normal writes/deletions; busy refresh preservation; stopped-container startup and prune ordering; key wiping after write errors; account ID pins; timestamp units; and client startup retry.

Docker smoke checks cover read-only mounts, default seccomp, zero worker capabilities, native SSH PTY, private keyring restore, snapshot telemetry exclusions, and retention of provider cache metadata. Tests use synthetic credentials except the explicitly named live provider smoke scripts.

The recorded-runtime workflow was launched using the installed Node 22.23.2 executable and successfully ran tests under the recorded Node 26 runtime.

Antigravity native tracing confirmed tool execution and a workspace file write without bypassing permissions. It also exposed a provider timeout returning `SUCCESS` with an empty response; Principal now rejects that as an incomplete attempt. A live Principal worker subsequently read a random marker, wrote the expected output, and returned structured JSON using an explicit `/workspace` permission grant and `gemini-3.8-flash-medium`. Antigravity 1.3.1 was validated after the installed binary had updated from 1.3.0. Unsupported provider versions now fail during image build. Evidence is recorded in BUILD.json.

## Limits

Provider error objects still arrive through the worker process; they are not a cryptographic attestation from the provider. Worker processes share their container identity with the helper, as documented in ARCHITECTURE.md. Conservative classification prevents accidental state changes from prose but does not make hostile worker telemetry trustworthy.

Existing runs freeze their runtime image. Start a new run to use the rebuilt worker; resuming an old run retains its old image.

Final verification: **43 automated tests passed**, including a Node 22 launch using the recorded runtime. Codex live run `6a1ab610-9168-4194-ab4e-3bb24b0b2f70` completed and applied in its temporary repository. The Antigravity worker passed against the final image with a 240-second bounded test deadline. An earlier 90-second repeat timed out and failed safely; timeout diagnostics were improved. Docker isolation, SSH/keyring snapshot restoration, snapshot exclusions, and dashboard TTY navigation checks passed. All three enrolled accounts remained ready.
