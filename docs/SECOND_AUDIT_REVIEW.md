### Additional confirmed cleanup issue

Account removal swallowed logout errors, then deleted the vault/account even if runtime cleanup had retained a lease. It now refuses deletion whenever a lease remains after logout, preserving credentials and records until cleanup is confirmed.

### Network reference

Docker documents `com.docker.network.bridge.enable_icc` as the bridge option controlling inter-container connectivity: [Docker bridge network documentation](https://docs.docker.com/engine/network/drivers/bridge/). This option depends on Docker's host networking/firewall behavior; the current rootful host was tested, and rootless portability remains a release gate.

## Remaining evidence gaps

Long-lived native OAuth refresh, real quota exhaustion and multi-account recovery, same-account conversation continuation, concurrent two-account Antigravity inference, complete crash/power-loss fault injection, and rootless Docker/subuid configurations remain unverified end to end. The claim that Antigravity always expires tokens after exactly one hour was not verified here and should not be treated as an established requirement. Secret redaction and container networking do not protect against an administrator or an attacker who already controls the same host user/Docker daemon.

Existing runs retain their pinned image; start a new run for the rebuilt helper. A daemon already running older code must be stopped after its work completes, then the next CLI invocation starts the updated coordinator.
